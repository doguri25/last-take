# 라스트 테이크 · 영화 제작사

**정식 버전 1.4.3 — 모바일 선택창 안정화·최종 섭외 인물 교체**

**제작자: 도구리** · 2026-09-12

시나리오를 고르고 제작진을 모아 극장 또는 OTT로 영화를 선보이는 브라우저 경영 게임입니다. 시작 자본 150억 원, 제작사 10곳, 영화인 1,600명을 사용합니다. 인물·회사·관계·평가·계약금은 게임을 위한 가상 설정입니다. 실제 영화 시장의 수익 예측 도구가 아닙니다.

## 실행과 업데이트

API 키, 서버 데이터베이스, 별도 빌드가 필요하지 않습니다. **`dist` 폴더 내용 전체가 실행·배포 파일**입니다. ES 모듈을 사용하므로 `index.html`을 파일 탐색기에서 직접 열지 말고 정적 웹 서버로 실행합니다.

```sh
python -m http.server 8080 --directory dist
```

브라우저에서 `http://localhost:8080`을 엽니다. 기존 배포를 갱신할 때는 `app.js`나 `index.html`만 교체하지 말고 새 JavaScript/CSS 파일을 포함해 `dist` 전체를 반영하세요. 이전 화면이 남아 있으면 강력 새로고침을 하되, 진행을 유지하려면 사이트 저장 데이터는 삭제하지 마세요.

**동봉 파일은 소스 및 로컬 커밋 패키지입니다. 이번 작업에서 GitHub 원격 푸시나 기존 실행 주소 재배포는 수행하지 않았습니다.**

## 1.4.3 변경 사항

### 모바일 세부장르 선택창

세부장르 선택을 확정할 때 기존 `<select>`를 제거하거나 다시 만들지 않습니다. 선택 값과 조화·충돌 설명, 조합 품질 안내만 갱신합니다. 터치 환경에서는 선택 후 포커스를 정리하고, 전체 화면을 다시 그리더라도 네이티브 선택창에 자동으로 포커스를 돌려주지 않습니다. 창 크기·모바일 표시 높이·배경 목록 높이가 바뀌어도 열린 제작 기획창을 재생성하지 않습니다.

이전 버전의 **세부장르 3열 배치, 모바일 시나리오 세로 스크롤, 인물 목록 페이지 방식**을 유지합니다. 데스크톱에서는 키보드로 선택할 때 포커스를 불필요하게 해제하지 않습니다.

### 최종 섭외 조건에서 인물별 교체

최종 제작 확인 단계의 **‘최종 섭외 조건 · 인물 교체’**로 들어갈 수 있습니다. 최종 섭외 목록에 있는 **감독 1명·주연 2명·조연 4명** 모두에게 ‘교체’ 버튼이 있습니다. 참여 수락·추가 조건·거절 상태와 관계없이 다른 인물을 찾을 수 있습니다. 각본은 선택한 시나리오에 연결된 기존 작가를 유지합니다.

**교체 → 같은 직군의 후보 선택 → 후보 답장 확인 → 조건을 수락하고 교체 → 전체 섭외 조건 재확인** 순서입니다. 후보를 확인하기만 하거나 취소하면 기존 인물과 수락 기록이 바뀌지 않습니다. 이미 선정한 인물, 촬영 중인 인물, 배역·활동 상태에 맞지 않는 인물은 선택할 수 없습니다.

교체를 수락하면 새 감독·배우·작가·제작사의 관계와 시나리오, 장르를 바탕으로 감독·주연·조연 **전체 7명의 기본료·추가 요구·거절 여부**를 다시 계산합니다. 이전 조합에서 수락한 추가 개런티는 무효화하며, 새 조건을 확인해야 제작을 시작할 수 있습니다. 조건은 같은 조합에서 일관되게 계산합니다. 교체했다고 해서 모든 인물의 금액이 반드시 바뀌는 것은 아닙니다.

후보 답장의 닫기/다른 인물 찾아보기는 후보 목록으로, 교체 후보 목록의 닫기/뒤로가기는 최종 섭외 조건으로 돌아갑니다. 이미 교체하거나 제작한 결과를 브라우저 기록으로 되돌리거나 중복 결제하지 않습니다. **비용은 제작 시작을 확정할 때 한 번만 지출**합니다. 저장 키와 이전 영화의 계약·실적·이미지는 변경하지 않았습니다.

개발 참고: 네이티브 `select`의 `change` 처리와 포커스 API를 확인했으며, 실제 모바일 OS의 선택 패널은 기기별 별도 확인이 필요합니다. https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/change_event · https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement

## 1.4.2 변경 사항

- 첫 화면의 제목은 **“당신의 영화사가 시작되는 순간.”**이다. 줄바꿈을 숨기는 모바일에서도 ‘영화사가’와 ‘시작되는’ 사이의 공백을 유지한다. 저장하고 첫 화면으로 돌아가도 같은 문구를 사용한다.
- 안경 렌즈가 겹치던 계산을 고쳤다. 남녀·성인/중년/노년·원본 사진별 눈 위치에 인물별 얼굴 변형, 좌우 반전과 기울기를 함께 적용해 렌즈와 코다리를 정렬한다. 기존 인물 ID와 기본 사진·얼굴 조합은 유지한다.
- 모바일 기획 화면의 세부장르 선택창은 **한 줄 3열**이다. 긴 항목은 선택창을 열어 전체 이름을 확인할 수 있다.
- **모바일 시나리오 제안은 모든 제안을 한 목록으로 표시하며 세로로 스크롤한다.** ‘이전/다음’으로 나누지 않는다. 검색·장르 필터는 유지하고 마지막 카드의 버튼도 고정 하단 메뉴 위로 스크롤할 수 있다. 인물정보 및 PC 시나리오는 기존 페이지 방식을 유지한다.
- 특수상영은 준비비·제작 규모·러닝타임·장르 작업량으로 추가 비용을 계산한다. 각 체크 항목에 실제 게임 견적을 표시하며 **선택만으로 지출하지 않는다.** 아래 ‘특수상영 제작 옵션’과 `PRESENTATION_COST_MODEL.md`에서 수치와 단순화 범위를 확인한다.
- 모바일 뒤로가기, 하단 진행 버튼, 더보기 복귀를 유지한다. 저장 키와 스키마는 변경하지 않으며 기존 계약·비용·정산을 소급 변경하지 않는다.

### 능력치와 저장 호환

실력(15~96), 인지도(1~97), 협업(20~98)은 제한된 범위에서 점진적으로 변합니다. 내부의 소수 변화가 쌓여야 화면의 정수 점수가 바뀌므로, 모든 인물이 매주 반드시 1점씩 변하지는 않습니다. 같은 주를 다시 계산하거나 저장을 다시 열어 성장 보상을 반복해서 받는 것은 막았습니다. 은퇴·별세 인물의 능력치는 고정합니다.

업데이트 시점의 현재 능력치를 기록 시작값으로 사용합니다. 없던 과거 성장 이력을 만들지 않고, 영화의 **계약 당시 제작진 능력치 스냅숏·기존 계약금·과거 흥행**은 바꾸지 않습니다. 새로운 세대의 인물은 독립적인 기록을 시작합니다. 게임 내 기존 세금/재무 시스템과 저장 키는 유지합니다.

### 원작과 주간 사건의 규칙

원작 정보 열람과 기획만으로 선급금이 빠지지 않습니다. 실제 제작 확정의 기존 비용 계산을 유지하며, 현재 제안에 없는 작품을 새로 기획하는 우회 요청은 거부합니다. 현재 두 제안의 상세정보에는 세계관·등장인물·저자·매체·계약 조건이 계속 표시됩니다.

자동 현장 소식은 대체로 주간 진행 때 발생하며, 최근 10종의 반복을 피합니다. 작은 작품 품질·홍보 인지도 변화가 있을 수 있지만, **자동 사건이 임의로 현금을 차감하지 않습니다.** 작품당 누적 품질 변화는 -3~+3, 홍보 인지도 변화는 -4~+6 범위로 제한합니다. 비용이 드는 기존 선택형 사건은 선택지를 보고 결정하는 방식입니다. 모든 권리는 실제 작품·플랫폼과 무관한 게임용 가상 설정입니다.

### 화면 구성과 적용 범위

화면 너비·높이와 방향이 바뀌면 목록 페이지당 카드 수를 다시 계산합니다. 작은 가로 화면에서는 카드의 부가 문구를 덜어내지만 인물 상세·시나리오 상세·기획 버튼과 페이지 이동은 남깁니다. **인물 상세, 라이선스 상세, 기획/캐스팅 창처럼 긴 정보를 읽는 팝업에는 필요한 스크롤을 유지**합니다. 목록 화면 밖에서는 이전의 일반 스크롤을 복구합니다.

### 러닝타임과 후반 편집

아래 표는 게임용 상영 여력 모델입니다. **하루 상영 가능 시간 12시간 + 회차 사이 정리 시간 20분**을 가정하며, 실제 극장의 편성표를 예측하거나 실제 규칙을 재현한 수치는 아닙니다.

| 러닝타임 | 하루 상영 회차 모델 | 120분 대비 상영 여력 | 기술 제작비 배수 |
| --- | --- | --- | --- |
| 90분 | 6회 | 1.2배 | 0.94배 |
| 120분 | 5회 | 1.0배 | 1.00배 |
| 150분 | 4회 | 0.8배 | 1.14배 |
| 180분 | 3회 | 0.6배 | 1.30배 |

상영 여력은 개봉 초기의 관객 수 산정에 반영됩니다. 실제 게임 수익은 작품성·인지도·홍보·경쟁·입소문·관객 수요에도 좌우되므로 90분을 선택했다고 언제나 가장 큰 수익이 나는 것은 아닙니다. 이후 관객 감소에 회차 계수를 매주 중복으로 곱하지 않습니다. OTT는 극장 상영 회차로 시청자 수나 계약금을 기계적으로 줄이지 않습니다.

원작 권장 호흡과 장르에 맞는 러닝타임은 품질에 유리합니다. 새 영화의 기술 제작비에 러닝타임 배수를 적용하지만, 작가 계약금과 배우 개런티 전체에 일괄 가산하지 않습니다. 처음 기획한 러닝타임과 최종 러닝타임을 각각 보관합니다.

촬영 완료 후 **후반작업 기간**에 `후반 편집` 알림 또는 영화 상세/제작 관리의 편집 메뉴를 엽니다. 다른 현장 결정과 제작진 공석을 먼저 해결해야 합니다. 감독은 성향·협업 능력·제작사 친밀도·편집안과 선호 호흡의 차이에 따라 동의하거나 갈등을 표시합니다. 편집안을 제안하는 것만으로 돈이나 품질이 바뀌지는 않습니다.

동의한 경우에는 편집 확정 또는 원안 유지가 가능합니다. 갈등이 있으면 **감독과 협의해 편집 / 제작사 편집 강행 / 원안 유지** 중 선택합니다. 각각의 예상 편집비·품질·감독 친밀도 변화를 결정 전에 표시합니다. 공동 편집은 비용이 늘지만 갈등을 완화하고, 강행은 관계와 품질에 추가 불이익이 있습니다. 같은 조건으로 취소 후 다시 제안해도 결과가 재추첨되지 않습니다.

결정 확정 시에만 비용을 한 번 차감하고 품질과 친밀도를 반영합니다. **제작 주기별 실제 편집은 한 번**만 가능합니다. 작품당 허용된 추가 제작을 별도로 시작하면 그 추가 제작의 후반작업에 한 번 더 편집할 수 있습니다. 미결 편집안이 있으면 주간 진행을 잠시 막고 결정을 안내합니다. 변경 내역은 제작 기록에 남습니다.

### 세금의 적용 범위

**한국의 2026년 일반 내국법인 세율과 법인지방소득세 표준세율**을 사용한 게임용 계산입니다. 과세표준 2억·200억·3,000억 구간에 국세 10/20/22/25%, 지방세 1/2/2.2/2.5%를 각각 누진 적용합니다. 일반 법인 기준의 15년 이월결손금과 양(+)의 소득 80% 공제 한도를 반영합니다.

월 운영비의 세금 부분은 **그때까지 발생한 연간 누적 소득으로 다시 계산한 예상 세금과 기적립액의 차이**입니다. 매달 연간 세금을 새로 전액 부과하지 않습니다. 후속 제작비 등으로 소득이 줄면 과다 적립분을 가용 현금으로 돌려줍니다. 자본금·대출 수령·원금 상환은 과세 수익/비용에서 제외합니다. 월 결산은 4주마다 한 번, 연말 정리는 중복 출금 없이 수행합니다.

이는 실제 월별 납부 제도가 아니라 게임의 지출 흐름을 위한 적립 방식입니다. 제작비 지출을 즉시 비용으로 처리하며, 부가가치세·원천징수·제작 자산화/감가상각·중소기업 특별 규정·각종 공제감면·실제 신고/납부 기한은 재현하지 않습니다. 일반 법인 이외의 특례를 임의로 적용하지 않습니다. **실제 세금 신고나 상담에 사용할 수 없습니다.** 법령 출처와 상세 설계는 `TAX_MODEL.md`에 있습니다.

### 기존 저장

기존 영화는 러닝타임 정보가 없으므로 **120분 기본값**으로 이전합니다. 이미 계산한 과거 관객·매출·품질·제작비를 소급 변경하지 않습니다. 과거 입출금 기록을 세금 목적으로 재정산하지 않으며, **업데이트 후부터** 소득과 비용을 누적합니다. 기존 v7 저장 키와 영화·인물 식별자를 유지합니다. 새 필드가 필요한 버전이므로 v1.3.0 저장을 구버전에서 다시 진행하는 것은 권장하지 않습니다.

## 평점과 흥행

새 작품의 평론은 7개 관점의 점수를 평균합니다. 평론과 관객 평점은 독립된 규칙을 사용하므로 점수가 서로 다를 수 있습니다. 관객 평은 극장 개봉 후 첫 1주 집계가 이루어지면 도착합니다. OTT는 계약 후 1주를 진행하면 시청자 평가가 도착합니다. 공개 전에는 임의의 관객 점수를 표시하지 않습니다.

평가자의 점수와 글은 작품 조건을 바탕으로 고정됩니다. 상세 창을 다시 열거나 새로고침한다고 유리한 평가로 다시 추첨되지 않습니다. 평론은 게임 안에서 작성한 가상 감상이며 실제 평론가나 온라인 이용자의 리뷰를 가져온 것이 아닙니다. 줄거리도 외부 생성 API 없이 로컬에서 구성합니다.

기존 버전에서 **이미 극장 개봉한 작품의 당시 평점·과거 관객·정산은 보존**합니다. 미개봉 완성작과 새 완성작에는 새 평론 기준을 적용합니다. 업데이트 후 집계되는 흥행에는 낮춘 새 관객 모델을 사용하므로, 상영 중이던 작품은 업데이트 이후의 주간 하락 폭이 달라질 수 있습니다. 과거 흥행 수치를 소급해 줄이거나 돈을 회수하지 않습니다.

게임 밸런스 계수는 보수적인 흥행을 만들기 위한 설계값입니다. 특정 실제 연도의 흥행 분포·제작비 회수율을 정확히 재현했다는 의미는 아닙니다. 소규모·장르·OTT 작품에도 실패할 가능성이 있으며, 높은 평점이 수익을 보장하지 않습니다.

**준비비 + 촬영·후반 기준비 × 작업률 × 러닝타임/120 × 장르 작업량**을 형식별로 계산한 뒤 합산한다.

| 4D | 0.25억 | 1.5% |
| IMAX | 1.20억 | 12% |
| 사운드 특화 | 0.20억 | 2% |

작가 계약금·배우 개런티·원작료에는 이 비율을 곱하지 않는다. 120분보다 긴 영화는 변동 작업비가 늘고, 짧은 영화는 줄어든다. 장르별 추가 작업량도 반영하므로 실제 선택 화면의 견적을 확인한다. 예를 들어 기준비 22억의 120분 드라마는 3D 6.34억, 4D 0.58억, IMAX 3.84억, 사운드 0.64억을 추가해 모두 선택하면 11.40억이다.

**위 수치는 실제 업체 요금표가 아닌 게임용 추정 계수다.** IMAX 옵션은 대형 화면 대응 촬영과 후반작업을 함께 다루며, 극장 설비 구매비나 실제 별도 매출 배분 계약까지 재현하지 않는다. 근거 자료와 계산식, 이전 계약 보존 정책은 `PRESENTATION_COST_MODEL.md`에 있다.

품질 보너스 합계는 최대 +6이며 제한된 평균 티켓 프리미엄은 유지한다. 비용을 많이 쓴다는 이유만으로 높은 평점이나 흥행을 보장하지 않는다. 확정된 영화의 기술 제작비는 새 요율로 다시 계산하지 않는다.

## OTT 계약

게임 속 OTT는 **네모플릭스 / 디즈링+ / 웨이브릿 / 티브링 / 쿠션플레이**입니다. 실존 서비스에서 이름을 연상할 수 있는 패러디 설정이며 실제 제휴·계약·추천 관계가 없습니다. 로고는 별도로 구성한 간단한 기하학적 아이콘과 가상 워드마크입니다.

완성된 미개봉 영화의 상세 화면이나 **OTT 상영관**에서 계약을 시작합니다. 진행 순서는 **제안 비교 → 한 곳 선택 → 계약 확인 → 독점 공개·계약금 수령**입니다. 플랫폼 선택만으로 돈이나 작품 상태가 바뀌지 않습니다.

제안금은 최초 제작 예산·작품 품질·장르·시청 호응 예상과 플랫폼의 선호를 반영합니다. 같은 영화와 조건이면 창을 다시 열어도 금액이 바뀌지 않습니다. 원작 라이선스가 있으면 약정 원작료를 공제하고 **실수령액을 현금과 누적 정산에 한 번만 반영**합니다. 총 계약금과 제작사 실수령액은 다를 수 있습니다.

OTT 독점 계약 후에는 그 영화를 극장 개봉하거나 다른 OTT에 다시 판매할 수 없습니다. 이미 개봉한 작품, 다른 제작사 작품, 제작 중인 작품은 판매할 수 없습니다. 홍보가 진행 중이면 완료 후 계약합니다. 극장 관객·극장 매출은 발생하지 않으며, OTT 목록에는 평론·시청자 평가를 별도로 표시합니다. 같은 작품을 중복 판매하거나 새로고침으로 계약금을 다시 받는 것을 차단합니다.

## 재무와 그래프의 기록 기준

신규 게임은 설립 자본부터 기록합니다. 거래·주간 진행마다 실제 잔액을 관측하고, 대출·상환·제작비·홍보비·극장/OTT 정산을 반영합니다. 같은 주의 여러 거래는 발생 순서대로 표시하며, 점이나 슬라이더를 짚으면 해당 날짜·값·설명을 확인할 수 있습니다.

이전 저장은 **남아 있는 거래 내역만** 현재 잔액에서 역산해 복원합니다. 이전 버전의 보관 한도를 넘어 이미 사라진 거래는 복원할 수 없으므로 해당 구간이 없다고 안내합니다. 월로만 남은 기록에 임의의 주간 날짜를 붙이지 않습니다. 저장되지 않은 극장 총매출 등은 가짜 0으로 채우지 않습니다.

‘현금 − 대출 잔액’은 그 두 금액의 차이일 뿐, 영화 판권 가치 등을 포함한 제작사의 총자산 평가가 아닙니다. 월 운영비 카드는 현재 기준의 기본 운영비·이자·예상 세금 적립 조정액이며, 해당 날짜의 실제 출금 합계와는 다릅니다. 그래프의 v1.3.0 이전 지점은 당시의 운영비와 이자만 보존합니다.

박스오피스의 상승/하락률은 같은 종류의 연속 주간 또는 월간 기록끼리만 비교합니다. 첫 기록은 NEW, 월/주 기록 전환이나 기록 간격이 있으면 비교 없음으로 표시합니다. 누적 관객 그래프는 실제 관람 기록을 합산합니다.

## 주간 달력·섭외·홍보

게임 달력은 **1개월 = 4주, 1년 = 48주**입니다. 독립·중규모·대규모 제작 기간은 24주·36주·48주, 추가 제작은 작품당 한 번 48주, 작품 간 개봉 간격은 8주입니다. 최대 3편을 동시에 제작할 수 있습니다. 월 운영비·이자·세금 적립은 네 번째 주의 월 결산에서만 반영합니다.

시나리오 ‘다시 받기’는 매회 **0.5억 원**으로 새 제안 6편을 받습니다. 이미 제작 중인 영화에는 영향을 주지 않습니다. 추가 개런티 조건은 기본 개런티의 15~40%이며, 수락만으로는 결제되지 않고 최종 제작 계약 시 비용에 반영합니다. 다른 영화에 참여 중인 인물은 돈을 더 준다고 섭외 제한을 우회하지 못합니다. 제작진을 바꾸면 관계·일정을 다시 확인합니다.

본 제작 **75%부터 홍보**할 수 있습니다. 홍보사 한 곳을 선택하고 시작하면 한 번만 결제하며 1주 뒤 결과를 알립니다. 같은 영화의 홍보를 동시에 중복 시작하지 못합니다. 제작 완료 시에는 완료 안내와 포스터 선택창이 열립니다. 극장 개봉 또는 OTT 공개 전까지 포스터를 변경할 수 있습니다.

극장 개봉 첫 8주는 매주 오른쪽 하단에서 성과를 알립니다. 이후에도 흥행 기록은 갱신됩니다. 중요한 생애·대흥행 소식도 같은 알림으로 표시하며 종 모양 버튼에서 최근 **500개**를 확인할 수 있습니다. 모달을 읽는 동안 알림은 대기합니다.

## 화면·키보드·저장 호환

스페이스키는 입력칸·검색·선택 컨트롤·한글 조합 입력 중에는 진행 단축키로 사용하지 않습니다. 기획 1/2단계에서는 ‘다음’, 일반 게임 화면에서는 ‘1주 진행’에 연결합니다. 결제·OTT 계약·새 제작사 설립은 실수 방지를 위해 버튼으로 별도 확정해야 합니다. Escape는 상세창에서 직전 화면으로 돌아갑니다.

자동 저장 키는 `last-take-game-v1`, 새 저장 형식은 **v7**입니다. 이전 v1~v6의 현금·영화·인물 ID·거래를 유지하며 이전합니다. 업데이트한 저장을 구버전으로 다시 읽히게 하는 역변환은 지원하지 않습니다. 웹 주소·포트·브라우저·기기를 바꾸면 저장이 자동으로 이동하지 않으므로 같은 주소로 업데이트하세요. 첫 화면 복귀는 저장 삭제가 아니며 ‘이어서 플레이’로 돌아올 수 있습니다.

시작 화면의 자동 비율 맞춤과 세로 스크롤 방지는 유지합니다. 긴 리뷰·회사 작품 목록·상세 기록 등 필요한 곳에는 내부 스크롤이 있습니다. 사용자 화면이 매우 작다고 텍스트까지 무조건 작게 만드는 대신 카드 페이지·접기·모달 내부 스크롤을 함께 사용합니다.

효과음은 Web Audio로 합성하며 음소거를 유지합니다. 전체화면을 허용하지 않는 브라우저에서는 ‘집중화면’으로 대체합니다. 집중화면은 브라우저 주소창을 제거하는 기능이 아닙니다.

Node 검사는 외부 패키지 설치 없이 실행합니다.

```sh
npm test
```

Playwright와 Chromium이 준비된 환경에서는 다음을 실행합니다.

```sh
python tests/studio-v14-browser.py --output qa-v14
# 아래는 이전 버전 회귀검사용입니다. 현재 결과는 TEST_RESULTS.md를 확인하세요.
python tests/studio-v13-browser.py --output qa-v13
python tests/studio-v12-browser.py --output qa-v12
python tests/weekly-browser.py --output qa-regression
python tests/start-screen-browser.py --output qa-layout
```

시스템 Chromium 경로는 `CHROMIUM_EXECUTABLE` 환경변수로 지정할 수 있습니다. 자세한 검사 결과와 제한은 `TEST_RESULTS.md`, 과거 버전은 `CHANGELOG.md`에 있습니다. 브라우저 검사는 오프라인 Chromium에 실제 제품 모듈과 PNG를 로드하는 방식이며, 실제 iPhone·Android 하드웨어나 원격 서비스 재배포까지 검사한 것은 아닙니다.
