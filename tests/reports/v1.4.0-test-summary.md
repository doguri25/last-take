## 로직 검사 범위

능력치의 주간 변화·동일 주 중복 계산 방지·은퇴 인물 고정·세대 교체·계약 당시 기록 불변·최근 32건 제한·장기 범위 제한·이전 저장 능력치와 현금 보존을 확인했습니다. 원작 40편/20종류의 상세 데이터·4주간 두 제안 유지·전체 카탈로그 순환·만료 제안 거절·기존 기획 유지, 21개 장르의 이야기와 세부 분류, 새 주간 사건과 진행 요약을 확인했습니다.

기존 영화 제작/추가 제작·섭외·초상화·평가·OTT·박스오피스·정산·러닝타임·세금·은퇴·저장 관련 Node 검사도 전체 실행했습니다. 여기에는 192주 장기 시뮬레이션이 포함됩니다. 증가한 콘텐츠 개수에 맞게 기존의 고정 개수 검사를 갱신하고, 새 이야기 32편 모두의 개별 전개도 검사했습니다.

## 재현

```sh
npm test
python tests/studio-v14-browser.py --output qa-v14
```

브라우저 검사에는 Python Playwright와 Chromium이 필요합니다. 코드가 바뀌지 않은 실제 제품 모듈, CSS와 PNG를 오프라인 blob import map으로 로드합니다. 테스트용 가상 인물/제작사 상태는 실제 게임 엔진의 생성·제작·주간 진행으로 준비합니다. 화면 조작은 실제 버튼과 입력 요소로 수행합니다.

## 기록과 한계

- `tests/reports/node-tests.txt`: 이번 전체 Node 실행 로그.
- `tests/reports/studio-v14-browser-report.json`: 이번 135개 확인 결과와 화면 측정치.
- `tests/reports/summary.json`: 이번 버전의 요약. 나머지 v1.2/v1.3/weekly/layout 보고서는 **과거 버전 기록**이며 이번 수치에 다시 합산하지 않았습니다.
- 실제 iPhone·Android 하드웨어, Safari의 소프트 키보드/주소창 변화, 운영 서비스의 네트워크·캐시 환경은 직접 검사하지 않았습니다.
- 외부 웹 서버/기존 실행 주소의 배포 검사가 아니라 오프라인 Chromium 제품 코드 검사입니다. 원격 푸시와 재배포는 이번 작업에서 수행하지 않았습니다.
- 푸시 도우미는 일반 푸시만 사용하며, 별도의 사용자 PC에서 GitHub 인증이 필요합니다. Windows CMD는 이 환경에서 실행하지 않았습니다.
